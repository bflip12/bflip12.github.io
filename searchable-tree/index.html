How to Search an Ant Design Tree Without Breaking Its Checkboxes

Filtering hides nodes that the checkbox cascade still needs. Here is how to keep the selection correct while the user searches.

React + TypeScript / Ant Design 4 / 6 min read

Based on a feature I built and shipped for a tree of about 1,200 nodes. The code is simplified to show the pattern, and the companion demo runs the same functions. Written with AI assistance.

Why filter the tree

Ant Design's own searchable Tree example highlights matching titles and expands the folders above them. Every node stays in the tree. That works when the tree is small enough to scan.

It works less well at scale. The tree I built this for held about 1,200 layers in nested folders. Highlighting left all 1,200 rows in place, with the matches spread across expanded folders the user still had to scroll through. Filtering shows only the matches and the folders that lead to them.

The other reason is what users do next. Search is usually the first half of a selection: find the items, then check them. antd's searchable example is not checkable, so it never has to decide what a folder's checkbox should show when some of its children are hidden. A filtered, checkable tree does, and that is where the problem starts.

The problem

Ant Design's Tree comes with a checkbox cascade. Check every child and the parent checks itself. Check some and the parent shows half-checked.

Add search by filtering treeData, and the cascade starts working from the filtered tree. A folder's state is computed only from the children still in treeData. Whatever the search hid stops counting.

The display is only half of it. antd drops any checked key that is not in the current treeData, so the next click reports a selection built from the visible nodes alone. Hidden selections are missing from it, and a folder whose visible children are all checked comes back as a checked folder. If your onCheck stores what it receives, one click during a search can remove items the user cannot see, or add them.

The fix has two halves. Rendering reads from the full tree, so hidden nodes still count. Clicks write only to the visible tree, so they never change what the user cannot see. The steps below build both.

Step 1

Decide how you store checked keys

Everything below starts from one piece of state: the keys the user has checked. There are two reasonable shapes for it, and the code differs in a few places depending on which you have. Pick yours and the rest of the article follows it. 

type TreeNode = { key: string; title: string; children?: TreeNode[] };

// Leaves plus fully checked folders, exactly as onCheck returns them.
const [checkedKeys, setCheckedKeys] = useState<string[]>([]);
type TreeNode = { key: string; title: string; children?: TreeNode[] };

// Leaf keys only. Folder state is always derived.
const [checkedKeys, setCheckedKeys] = useState<string[]>([]);

const collectLeafKeys = (nodes: TreeNode[], out = new Set<string>()) => {
  for (const node of nodes) {
    if (node.children?.length) collectLeafKeys(node.children, out);
    else out.add(node.key);
  }
  return out;
};

const leafKeys = useMemo(() => collectLeafKeys(fullTree), [fullTree]);

The app I built this for already stored antd's format, so it needed the extra sync step at the end of Step 5.

Step 2

Filter the tree

A plain filter keeps nodes whose title matches, which breaks on folders: search a folder's name and you get the folder with none of its contents. So a matching folder keeps all its children.

Expanding is a separate decision. Open the folders on the path to a match, but leave a matching folder itself closed, or its whole contents push the other results off screen. 

const filterTree = (nodes: TreeNode[], query: string, expanded: Set<string>): TreeNode[] => {
  const result: TreeNode[] = [];

  for (const node of nodes) {
    const matches = node.title.toLowerCase().includes(query);

    if (node.children?.length) {
      if (matches) {
        // A matching folder keeps everything inside it.
        result.push(node);
        continue;
      }
      const children = filterTree(node.children, query, expanded);
      if (children.length) {
        // Something inside matched, so open this folder to show it.
        expanded.add(node.key);
        result.push({ ...node, children });
      }
    } else if (matches) {
      result.push(node);
    }
  }

  return result;
};

Because a matching folder brings its children along, not every visible row matches the query. That is intended.

Step 3

Turn on checkStrictly while searching

checkStrictly turns off antd's cascade. antd then renders exactly the checked and half-checked keys you pass it. Switch it on only while a search is active. Without a search, the cascade is correct and costs you nothing. 

const isSearching = query.trim().length > 0;

<Tree
  checkable
  checkStrictly={isSearching}
  treeData={isSearching ? search.tree : fullTree}
  checkedKeys={isSearching ? searchCheckState : checkedKeys}
  onCheck={handleCheck}
  expandedKeys={expandedKeys}
  onExpand={(keys) => setExpandedKeys(keys as string[])}
/>

In strict mode checkedKeys takes an object, { checked, halfChecked }, instead of an array. The next step builds it.

Step 4

Compute checkbox state from the full tree

While searching, you supply both lists yourself. Walk the full tree, not the filtered one, and count the leaves under each folder. All selected means checked, some means half-checked, none means unchecked. 

type CheckState = { checked: string[]; halfChecked: string[] };

// Walks the full tree, so leaves hidden by the search still count.
const deriveCheckState = (nodes: TreeNode[], selected: Set<string>, out: CheckState) => {
  let total = 0;
  let picked = 0;

  for (const node of nodes) {
    if (!node.children?.length) {
      total += 1;
      if (selected.has(node.key)) {
        picked += 1;
        out.checked.push(node.key);
      }
      continue;
    }

    const sub = deriveCheckState(node.children, selected, out);
    if (sub.total > 0 && sub.picked === sub.total) out.checked.push(node.key);
    else if (sub.picked > 0) out.halfChecked.push(node.key);

    total += sub.total;
    picked += sub.picked;
  }

  return { total, picked };
};

const searchCheckState = useMemo(() => {
  const out: CheckState = { checked: [], halfChecked: [] };
  deriveCheckState(fullTree, new Set(checkedKeys), out);
  return out;
}, [fullTree, checkedKeys]);

It reads leaf keys only, so it works with either storage format. Folder keys in the list are ignored.

Step 5

Apply clicks only to what is visible

In strict mode, onCheck no longer works anything out for you. It hands you the clicked node and you update the state yourself. That node comes from the filtered tree, so its children are only the ones the user can see. Recursing from it cannot reach hidden nodes. 

const allLeavesChecked = (node: TreeNode, selected: Set<string>): boolean =>
  node.children?.length
    ? node.children.every((child) => allLeavesChecked(child, selected))
    : selected.has(node.key);

const applyToggle = (node: TreeNode, add: boolean, selected: Set<string>) => {
  if (node.children?.length) {
    node.children.forEach((child) => applyToggle(child, add, selected));
  } else if (add) {
    selected.add(node.key);
  } else {
    selected.delete(node.key);
  }
};

Do not use info.checked to decide the direction. For a half-checked folder it reports true even when every visible child is already checked, so the click appears to do nothing. Decide from the visible leaves instead: if they are all checked, uncheck them, otherwise check them. One rule covers leaves, folders, and half-checked folders. 

const handleCheck: TreeProps["onCheck"] = (keys, info) => {
  if (!isSearching) {
    // No search: antd's cascade is correct, so store what it returns.
    setCheckedKeys(keys as string[]);
    return;
  }

  const next = new Set(checkedKeys);
  const node = info.node as TreeNode; // from the filtered tree

  applyToggle(node, !allLeavesChecked(node, next), next);
  syncFolderKeys(fullTree, next); // keep antd's format valid

  setCheckedKeys([...next]);
};
const handleCheck: TreeProps["onCheck"] = (keys, info) => {
  if (!isSearching) {
    // No search: antd's cascade is correct. Keep only the leaves it returns.
    setCheckedKeys((keys as string[]).filter((key) => leafKeys.has(key)));
    return;
  }

  const next = new Set(checkedKeys);
  const node = info.node as TreeNode; // from the filtered tree

  applyToggle(node, !allLeavesChecked(node, next), next);

  setCheckedKeys([...next]);
};

Keep folder keys in sync

antd's format promises that a folder key is present exactly when every leaf under it is checked. A toggle during search changes leaves only, so walk the full tree afterwards and add or remove folder keys to match. 

// Returns whether every leaf under `nodes` is selected.
const syncFolderKeys = (nodes: TreeNode[], selected: Set<string>): boolean => {
  let allSelected = true;

  for (const node of nodes) {
    if (node.children?.length) {
      const full = syncFolderKeys(node.children, selected);
      if (full) selected.add(node.key);
      else selected.delete(node.key);
      allSelected = allSelected && full;
    } else {
      allSelected = allSelected && selected.has(node.key);
    }
  }

  return allSelected;
};
Why this step matters Skip it and the damage shows up when the search clears. Say North stays in the list after one of its sites is unchecked. The tree goes back to cascade mode, reads North as checked, and checks every site under it, including ones the user never picked.

With leaves only there is nothing else to update. Folder keys are never stored, so none can go out of date.

Debounce the filter, not the input

Rebuilding a large tree on every keystroke makes typing lag. Debouncing the input's value fixes that but makes the text field itself feel slow. Keep the input immediate and debounce only the query that drives the filter. 

const [inputValue, setInputValue] = useState("");
const [query, setQuery] = useState("");

// Created once. A new debounced function on every render
// would reset the timer on every keystroke.
const updateQuery = useMemo(() => debounce(setQuery, 250), []);
useEffect(() => () => updateQuery.cancel(), [updateQuery]);

const search = useMemo(() => {
  const expanded = new Set<string>();
  const tree = filterTree(fullTree, query.trim().toLowerCase(), expanded);
  return { tree, expandedKeys: [...expanded] };
}, [fullTree, query]);

<Input
  value={inputValue}
  onChange={(e) => {
    setInputValue(e.target.value); // the input stays responsive
    updateQuery(e.target.value);   // the filter waits
  }}
/>

Because the filtered tree is derived from state, anything that changes fullTree, such as a rename elsewhere in the app, re-runs the current search on its own. Seed expandedKeys from search.expandedKeys whenever the query changes, so the user can still open and close folders in the results.

Summary

Read from the full tree, write to the visible one. What renders has to account for the nodes the filter hid. What a click changes must not.
  • Filter the tree, keeping matching folders whole.
  • Turn on checkStrictly only while searching.
  • Derive checked and half-checked states from the full tree.
  • Apply each click to the visible children of the clicked node.
  • If you store antd's format, sync folder keys after every change.
